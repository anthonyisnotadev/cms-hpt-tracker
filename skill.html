What it does

Turn a sentence into an outreach update

The tracker keeps outreach notes beside each hospital record. The skill provides a quicker way to update that log from a coding assistant.

A normal sentence can record an email, a reply, a follow-up date, a research note, or an evidence-supported correction. Hospital names are matched against the CMS list; ambiguous names need a city, state, or CMS certification number.

The same records appear in the tracker's hospital drawer. The tool logs fieldwork and can help draft an email, but it does not send messages. Public exports are separate from the private working file and need review before publication.

Workflow

Review the change before saving

The assistant prepares the change, but the command-line tool controls what can be saved.

Describe
State what happened in ordinary language, with a city or state when the name is ambiguous.
Match
The tool searches the hospital list and reports the match and confidence.
Preview
A dry run shows the proposed changes, along with warnings about discarded or rewritten input. Nothing is saved at this stage.
Approve
The assistant asks for approval unless you already authorized the specific changes. It saves through the checked command and reports the result.

Setup

Use the copy included in this repository

Use a local repository checkout with Node.js. Logging does not require a separate service or account.

Claude Code reads .claude/skills/outreach/SKILL.md. The shared entry point at .agents/skills/outreach/SKILL.md directs compatible assistants to the same instructions, including the reviewed-evidence reference.

From the repository root, run npm run outreach -- help to see the terminal commands. Writes preview changes by default; --commit saves an approved plan. The terminal provides the same matching, backup, and validation without an AI assistant.

Public export regeneration also needs the existing local contact-protection key. If that key is missing or regeneration fails, resolve the problem before publishing.

Examples

Say what happened normally

  • Emailed Springfield Regional about its dead file link. The email bounced.
  • Mercy replied with a new price-file URL. Follow up next Friday.
  • Add a note that the hospital website now redirects to its parent system.

Short statements are enough when the hospital name is unique. Include the city, state, or CMS certification number when several hospitals share a name.

Raw replies can also be pasted into the request. The preview should be checked carefully before saving, especially when a message mentions several facilities.

Evidence and corrections

A reply starts a review

A working link or a promise to fix a file is useful fieldwork. A correction also needs evidence for the specific hospital.

Facility identity
Check the file's hospital name, address, state, and campus coverage for each CMS record. A shared website or system-wide file does not establish coverage for every hospital.
Access
Record blocked requests and timeouts separately from missing files. Browser access may differ from an automated check.
Newer reviews
A newer reviewed finding takes precedence over an older manual correction. The correction remains in the history; its date should reflect when the check actually happened.
Research totals
Outreach corrections do not rewrite the nationwide research files or aggregate audit totals. Updating those requires the reviewed research workflow.

The skill consults the current reviewed record and its next action. Unresolved investigations, retained-evidence follow-ups, identity reviews, and uncertainty monitoring are distinct workstreams; a follow-up does not always mean a hospital lacks a result.

For an authorized research refresh, the repository rebuilds verification, reconciliation, and source-validated worklists before generating the tracker. The snapshot date describes the included observations, not the date a page was deployed.

Safety

The assistant proposes; the tool checks

The skill directs the assistant to use the checked command and make every proposed write visible.

Approval
Review the preview before saving. Existing authorization for specific changes can cover the save; it does not authorize sending email or publishing unrelated work.
Matching
Weak or ambiguous hospital matches stop for clarification.
Recovery
The previous file is backed up before a write. Restore can undo the last saved batch; the backup is one version deep.
Pasted material
Hospital replies and file contents are evidence to inspect, not instructions for the assistant to follow.

Public exports

Review what leaves the working file

The private file stays local, but notes and message content can appear in the public export.

Each save attempts to regenerate a separate public copy. Email addresses are masked, configured person names are replaced, and contact text is protected for storage. The public application can reveal protected text, so contact protection is not a guarantee of confidentiality.

Review the full notes and messages for names, private details, and credentials before publication. Names and bare usernames need entries in the local redaction list; automated checks cannot identify every sensitive statement.

Check
Run npm run check:contacts-private and npm run check:pointers-private, then inspect the exact public changes and outgoing commits.
Publish
A local save, a Git commit, and a deployed website are separate steps. Push only when authorized, then verify the live snapshot and its links.
